## Why

Users can currently verify translated solutions, but they cannot measure runtime consistency or memory cost through the same generated tester workflow. A dedicated `profile` command makes performance checks repeatable while preserving the existing `generate`-then-run model.

## What Changes

- Add a root-level `profile <tests_dir> <solution_path> --lang <target_lang> [flags...]` command.
- Require the language-specific tester generated by `generate` to exist before profiling.
- Support repeated profiling with `-n <trials>`, optional warmup runs via `--warmup <k>`, and runtime mean/std JSON output.
- Support optional memory aggregation via `--memory`.
- Support the same selection, timeout, and tolerance flags as `test`: `--list-tests`, `--run`, `--timeout-ms`, `--total-timeout-ms`, and `--tol`.
- Include timed-out runs in aggregate statistics and report timed-out test IDs in `failed`.

## Impact

- Affects the root `babel_code_goat.py` CLI argument parser and command dispatch.
- Reuses or extends generated tester execution paths used by `test`.
- Adds test coverage for profiling output, warmup exclusion, memory aggregation, missing tester errors, flag parity, and timeout aggregation.
